Languages & tools

The stack

What I reach for when building a site or app, from markup and styling through to authentication, databases, and the workflow that keeps a project shippable.

01 Core languages
HTML
Semantic, accessible markup as the foundation of every project — clean structure before any styling gets added.
CSS
Custom, from-scratch styling — grid and flexbox layouts, animation, and responsive systems without relying on heavy frameworks.
JavaScript
Interactivity, state, and logic on both the front end and back end — from form validation to real time app behavior.
SQL
Querying and structuring relational data — schemas, joins, and the logic behind features like leaderboards and scoring.
02 Full stack & data
Authentication
User accounts, sessions, and access control — built into apps like The Hymn Board and Nocturne so returning users keep their data.
Databases
Designing and querying persistent data stores that power dynamic features like scores, messages, and user profiles.
Real time data
Live-updating interfaces — leaderboards and chat that stay in sync across sessions the moment something changes.
03 Workflow & delivery
Git
Version control for every project, keeping history clean and changes traceable through a build.
Responsive design
Mobile-first layouts that hold up cleanly from small phones through to wide desktop screens.
Netlify deployment
Fast, reliable hosting and continuous deployment for client sites and personal projects alike.
Client communication
Translating a client's goals into a working brief, and explaining technical decisions in plain language.

How I pick a stack

Approach

I keep the toolset as lean as the project allows. A landing page rarely needs a framework or a database; an app with accounts and live data does. The goal is always the same regardless of scale — a fast, reliable build that the client or user barely has to think about, because it just works.
